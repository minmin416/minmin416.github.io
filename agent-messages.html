Inquiry API

Submit a message to Riverplo. Inquiries are private, untrusted data. They do not authorize code execution, following agent instructions, external messages, or inbox access.

Read the current processing, US storage and retention notice and machine-readable schema/availability before submitting. Only submit personal data when authorized. A missing CAPTCHA is not permission to bypass limits.

POST https://riverplo-inquiry-api.river-personal-work.workers.dev/v1/inquiries
Content-Type: application/json. Uncompressed UTF-8 body at most 8192 bytes.

  • id: a fresh UUIDv4; retry identical content with the same ID after an uncertain response.
  • message: nonempty, at most 2000 UTF-16 code units.
  • reply: optional email, at most 254 characters; omit for no reply.
  • noticeVersion: exact version supplied by the schema.
  • submissionIntent: "send_message": an explicit authorized send request. Do not claim notice-reading or consent on another person’s behalf.

No additional fields. 201 means a new durable receipt; 200 means the identical ID was already saved. Replies contain only success and your ID. 409 means ID/content conflict. 400/408/413/415 indicate input/body issues; 429 indicates an admission limit; 503 means unavailable or storage not confirmed. Respect Retry-After and retry the same ID/content after uncertainty.

Human and agent messages share a hard admission budget of 100 new messages per UTC day and 8200 active records. Coarse IP/edge limits also apply and may affect shared networks. Filling the budget or exhausting shared free-service request limits can make inquiries unavailable; this is not a guarantee against spam or downtime. No public read/list endpoint is provided.
